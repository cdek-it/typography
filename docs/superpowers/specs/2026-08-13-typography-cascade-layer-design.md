# Фикс каскада: типографика в `@layer components`

Дата: 2026-08-13
Ветка: `typography-cascade-layer`
Версия пакета: 3.2.2 → 4.0.0

## Проблема

Классы типографики задают `color`, но подключаются вне слоёв каскада. Unlayered CSS всегда
сильнее layered, поэтому утилиты Tailwind (слой `utilities`) и токен-утилиты не могут
переопределить цвет текста:

```html
<h2 class="title-h2 text-white">Заголовок на тёмном фоне</h2>
<!-- ожидаем белый, получаем #2B2E33 из .title-h2 -->

<p class="body-regular-base text-color-secondary">Подпись</p>
<!-- серый не применяется -->
```

Продуктовые команды вынуждены писать `text-white!` на каждом таком месте.

Цвет нельзя просто убрать из классов: он часть публичного API именования — из 183 селекторов
145 содержат цвет как смысловую часть (`-secondary`, `-disabled`, `-primary`, `-danger`
и т.д.). Убрав `color`, мы сломали бы семантику этих классов.

## Решение

Пакет сам объявляет порядок слоёв и кладёт всё своё содержимое в `components`:

```css
@layer theme, base, components, utilities;

@layer components {
    :root { /* токены */ }
    :root[data-theme="dark"] { /* токены тёмной темы */ }
    /* все 183 селектора без изменений */
}
```

### Почему слой `components`

Совпадает со слоем Tailwind, поэтому:

- `utilities` (все `text-*`) сильнее типографики — цвет переопределяется без `!`;
- `base` (preflight) слабее типографики — сбросы `h1..h6 { font-size: inherit }` не ломают
  заголовки;
- продуктовый `@layer components`, подключённый после пакета, тоже может переопределить
  типографику без `!` — равный слой, решает порядок в исходнике.

Поведение идентично уже проверенному в продукте обходу
`@import '@cdek-it/typography/dist/index.min.css' layer(components);`, но работает
и при подключении через CDN `<link>`, где `layer()` недоступен.

### Почему объявление порядка обязательно

Позиция слоя определяется его первым объявлением. Если пакет подключён до Tailwind и объявит
только `components`, порядок станет `components, theme, base, utilities` — preflight в `base`
окажется сильнее `.title-h2` и убьёт размеры заголовков. Строка
`@layer theme, base, components, utilities;` фиксирует корректный порядок независимо от
порядка импортов.

Для потребителей без Tailwind объявление пустых слоёв ничего не рендерит и не влияет на их
unlayered CSS — он остаётся сильнее любого слоя.

### Токены в слое

`:root` с переменными уходит внутрь слоя вместе с остальным. Это позволяет продуктам
переопределять токены (`--text-color` и прочие) обычным unlayered CSS. Переменные Prime
(`--p-*`) подставляются через `var()` и на каскад слоёв не завязаны.

## Совместимость

| Сценарий | До | После |
|---|---|---|
| `class="title-h2 text-white"` | ❌ | ✅ |
| `class="title-h2 text-white!"` (текущий обход) | ✅ | ✅ |
| Переопределение обычным CSS после импорта | ✅ | ✅ |
| Переопределение из `@layer base` у продукта | ❌ | ❌ (стало слабее осознанно) |
| Переопределение из `@layer components` у продукта | ❌ | ✅ |

Обходы `text-white!` продолжают работать (`!important` в `utilities` сильнее любого
non-important правила в `components`), поэтому чистить их можно постепенно.

Ломающим изменение делает смена силы каскада: правила, которые раньше проигрывали пакету,
теперь могут начать применяться. Отсюда мажорная версия 4.0.0.

## Объём работ

1. `typography.css` — объявление порядка слоёв + обёртка. Содержимое правил не меняется.
2. `package.json` — версия `4.0.0`. Сборка (`cleancss`) и workflow публикации без изменений:
   clean-css сохраняет `@layer` корректно (проверено).
3. `README.md` — раздел «Слои каскада (`@layer`)» с примерами и заметкой о миграции с 3.x;
   правка раздела «Переопределение стилей».

## Проверка

Тестовая страница с Tailwind, прогоняемая в браузере со сверкой `getComputedStyle().color`:

1. `title-h2` + `text-white` → белый;
2. `body-regular-base` + `text-color-secondary` → серый;
3. пакет импортирован **до** Tailwind → размеры заголовков не сброшены preflight;
4. `title-h2` + `text-white!` (старый обход) → белый;
5. тёмная тема (`data-theme="dark"`) → токены применяются.

Сверка до и после правки: сценарии 1–2 должны сменить статус с ❌ на ✅, остальные — остаться ✅.
